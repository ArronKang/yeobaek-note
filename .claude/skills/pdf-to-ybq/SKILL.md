# PDF → .ybq 변환

사용자가 준 PDF를 여백 노트에서 풀 수 있는 `.ybq` 문제지로 옮긴다. 결과는 **보기 누르기, 꾹 눌러 정답과 풀이 보기, 채점**이 되는 파일 하나다.

형식의 기준은 저장소의 `HANDOFF.md` 4장이다. 이 문서는 변환 순서와 판단 기준을 다룬다.

## 순서

### 1. PDF 읽기

작업 폴더는 스크래치패드에 만들고, PDF는 그 안의 빈 폴더에 둔다.

```bash
pdftotext -layout input.pdf out.txt          # 글자 (줄 배치 유지)
pdftoppm -r 110 -png input.pdf page          # 쪽 그림: page-1.png …
```

- 글자는 `out.txt`로 읽고, **모든 쪽 그림을 직접 열어 본다.** 수식, 보기 번호, 표, 그래프는 텍스트 추출이 자주 깨지므로 그림이 기준이다.
- 스캔본(글자가 거의 안 나옴)이면 쪽 그림을 보고 옮긴다.
- 쪽이 많으면 10쪽씩 나눠 읽는다.

### 2. 구조 파악

쪽을 보면서 아래 표를 머릿속으로 채운다.

| 찾을 것 | .ybq에서 |
|---|---|
| `[1~3] 다음 글을 읽고…` 같은 묶음 지시문과 지문 | `passage` (`q` = 지시문, `text` = 지문) |
| ①~⑤ 보기가 있는 문항 | `choice` (`choices`, `answer`는 1부터 세는 번호) |
| 답을 쓰는 문항 (단답·서술) | `short` (`answer`는 문자열) |
| 배점 `[3점]` | `points` |
| 정답표, 해설 | `answer`, `solution` |
| 문항에 딸린 그래프·도형·표 그림 | `img` (3단계) |

- 원래 번호 순서를 지킨다. `.ybq`는 번호를 자동으로 매기므로 `q`에 번호를 넣지 않는다.
- 제목은 PDF 표지나 머리글에서(`title`), 과목·학년은 `subject`에 짧게. **가운뎃점(·)은 쓰지 않는다** (앱 원칙).

### 3. 그림 잘라 넣기 (필요할 때만)

글로 옮길 수 없는 그래프, 도형, 복잡한 표만 그림으로 넣는다. 글로 옮길 수 있는 표는 글로 옮긴다.

```bash
python3 .claude/skills/pdf-to-ybq/scripts/crop.py page-3.png 120 410 980 760 --dpi 110
```

- 인자는 쪽 그림 위의 픽셀 사각형 `x0 y0 x1 y1`이다. 쪽 그림을 보고 좌표를 정하고, 잘린 결과(`crop_preview.png`)를 열어 확인한다.
- 출력은 문항에 그대로 넣는 JSON `{"src": "data:image/png;base64,...", "w": …, "h": …}`이다. 크기는 페이지 너비 560 기준으로 자동 계산된다.
- 그림 하나는 60KB 안팎, 문제지 전체는 2MB 이하로 유지한다. 앱이 기기 저장소에 넣기 때문이다.

### 4. 정답과 풀이

- **PDF에 정답표나 해설이 있으면 그대로 쓴다.**
- **없으면 직접 푼다.** 한 문항씩 풀고, 계산 문제는 `python3`로 검산한다. 확신이 없는 문항은 끝에 사용자에게 번호를 알려 준다.
- 풀이(`solution`)는 짧게, 핵심 단계만 쓴다. PDF 해설이 길면 요약한다.

### 5. 본문 표기

- 수식: `$...$`, 줄 수식 `$$...$$`. JSON 안에서는 역슬래시를 두 번(`\\frac`). 파이썬 `json.dump`로 쓰면 자동으로 처리된다.
- `**굵게**`, `__밑줄__`, 줄바꿈 `\n`, 빈칸 `____`는 그대로.
- 원문의 밑줄 친 부분, 굵은 글씨는 살린다.
- 풀이 공간 `space`: 객관식 기본 70, 계산이 긴 문항은 110~150, 단답 130.

### 6. 파일 만들고 검사

`build.py` 같은 스크립트를 스크래치패드에 쓰고, 파이썬 dict로 만든 뒤 `json.dump(..., ensure_ascii=False, indent=1)`로 저장한다. 그런 다음 아래 두 검사를 돌린다.

```bash
python3 .claude/skills/pdf-to-ybq/scripts/check.py out.ybq
node .claude/skills/pdf-to-ybq/scripts/render.js out.ybq shots/
```

- `check.py`: 형식, 정답 범위, 수식 짝(`$`), 그림 크기, 파일 크기, 문항 수를 검사한다. 경고는 고치고, 오류가 없어야 넘긴다.
- `render.js`: 저장소의 앱을 그대로 열어 `.ybq`를 가져오고 쪽마다 스크린샷을 남긴다. **스크린샷을 열어** 수식이 깨지지 않았는지, 그림이 맞는 문항에 붙었는지, 원본 PDF와 문항 수가 같은지 확인한다.

### 7. 전달

- 파일 이름은 PDF 이름을 따라 `<이름>.ybq`로 정하고, 사용자가 열 수 있는 곳(작업 폴더 또는 스크래치패드)에 둔 뒤 보낸다.
- 답장은 짧게 쓴다: 문항 수, 그림 넣은 문항, 직접 풀어서 정답을 단 문항(있으면), 확신이 낮은 문항 번호.
- 앱에서는 라이브러리의 가져오기 버튼으로 연다.

## 판단 기준

- 사용자가 준 자료를 본인 공부용으로 옮기는 작업이다. 내용은 원문 그대로 옮기고, 임의로 고쳐 쓰지 않는다.
- 문항을 빠뜨리지 않는다. 마지막에 PDF의 문항 수와 `.ybq` 문항 수를 맞춰 본다.
- 보기가 그림뿐인 문항(예: 그래프 ①~⑤)은 보기까지 포함한 영역을 `img`로 넣고, `choices`는 빈 글자 `["","","","",""]`로 둔다. 앱이 ①~⑤ 버튼만 한 줄로 그린다.
- 서술형처럼 채점 기준이 긴 문항은 `short`로 두고 `answer`에 핵심 답, `solution`에 채점 요소를 쓴다.
